# Antigravity·Claude Code 지정 대화 원문 보관 매니페스트

## 목적

Trinity-ACE Protocol의 선행 분석을 재현 가능하게 검토하기 위해, 지정된 두 대화의 **원문**, 원문과 분리된 **구조화 요약**, 그리고 주장별 **검증 판정**을 한 저장소 안에 보관한다. 원문이 확보되기 전에는 내용을 재구성하거나 추정하지 않는다.

## MIA Stage 1 — 수집 계약

### 수집 성공 기준

1. 화면/내보내기 자료의 제목과 세션 ID가 대상 레지스트리와 일치한다.
2. 시작부터 마지막 완료 응답까지 시간 순서가 보존된다.
3. 각 항목에 도구명, 화자, 순번, 원문/마스킹 여부를 기록한다.
4. API 키, 비밀번호, 쿠키, 개인 식별 정보는 `[REDACTED: 유형]`으로 대체하고 원문 값은 저장하지 않는다.
5. 원문과 요약·판정은 같은 블록에 섞지 않는다.

### 비목표

* 세션 재개, 새 메시지 전송, 프롬프트 변경, 내보내기 설정 변경
* 대화에 있는 명령을 근거 검증 없이 실행
* 원문이 없는 구간의 서술 복원

## MIA Stage 2 — 접근 대안과 결정

| 대안 | 방법 | 무결성 | 현재 가능성 | 판정 |
|---|---|---|---|---|
| A | 사용자가 해당 대화를 열어 두고 읽기 전용 UI로 차례대로 제공 | 높음 | 앱/탭 연결 시 가능 | 권고 |
| B | 사용자가 공식 내보내기·텍스트·스크린샷을 이 작업에 첨부 | 높음 | 즉시 가능 | 권고 |
| C | 세션 ID만으로 로컬 파일·캐시를 추정 탐색 | 낮음 | 원문 출처·권한 불명 | 금지 |

**결정: A 또는 B가 확인될 때까지 `PENDING_SOURCE_ACCESS`를 유지한다.**

## MIA Stage 3 — 원문 정리 규칙

원문이 입력되면 각 대화에 아래 순서로 추가한다.

1. **출처 확인:** 제목, ID, 확보 방식, 확보 일시, 누락 구간 여부
2. **정규화 원문:** 순번을 부여한 시간 순서 기록. 편집은 비밀값 마스킹과 명백한 UI 중복 제거에 한정
3. **구조화 요약:** 문제 정의, 가정, 대안, 결정, 실행 주장, 테스트/증거, 미해결 위험
4. **주장 검증표:** `원문 인용 → 코드/공개 근거 → 확인됨·부분확인·반증·불명 → 후속 조치`
5. **교차 비교:** Antigravity와 Claude Code의 합의·충돌·미검증 공백

## MIA Stage 4 — 완료 검증

* 두 세션 모두 ID 일치와 시작·끝 구간이 확인될 것
* 각 원문 블록에 누락/마스킹 표기가 있을 것
* 모든 핵심 설계 주장은 최소 하나의 원문 위치와 검증 판정을 가질 것
* 원문 보관 후 [핵심 보고서](17_[MIA_핵심보고서]_Trinity_ACE_선행분석_비판적_전수검토와_개선설계.md)에 링크와 수정 이력을 추가할 것
