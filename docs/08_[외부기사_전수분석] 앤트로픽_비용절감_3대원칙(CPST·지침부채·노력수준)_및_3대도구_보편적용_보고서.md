## 💡 1. ELI10 직관 요약 (10살도 이해하는 쉬운 비유)

### "100m당 요금이 싼 택시가 항상 싼 것은 아닙니다"
우리가 택시를 탈 때 100m당 요금이 싼 택시를 탔더라도, 길을 모르는 초보 기사님이 골목길을 3번이나 유턴하고 빙빙 돌았다면 결국 요금 폭탄을 맞게 됩니다. 반대로 100m당 요금이 조금 더 비싸더라도 내비게이션을 정확히 보고 단 한 번에 목적지에 도착한 베테랑 기사님의 택시가 최종 영수증은 훨씬 적게 나옵니다.

AI 코딩 도구(Codex, Claude, Antigravity)도 완전히 똑같습니다.
1. **진짜 비용의 기준 (CPST, 성공 작업당 비용)**: 인공지능에게 말을 건네는 글자 수(토큰) 하나의 가격만 따지는 것은 눈속임입니다. **"내가 시킨 일 하나를 오류 없이 완벽하게 끝내는 데 총얼마가 들었는가?"**를 따져야 진짜 절약이 됩니다.
2. **단골손님 전용 패스 (프롬프트 캐싱, Prompt Caching)**: 매번 식당에 갈 때마다 내 신분증과 주민등록등본을 길게 낭독하면 시간과 돈이 듭니다. 시스템이 이미 기억하고 있는 규칙(캐시)을 그대로 재사용하면 요금이 최대 85~90%까지 대폭 할인됩니다. 단, 식당 문 앞머리의 간판(접두사)을 매번 바꾸지 않는 **접두사 불변성**이 지켜져야 합니다.
3. **오래된 잔소리 털어내기 (지침 부채, Instruction Debt)**: 옛날 똑똑하지 못했던 2년 전 초창기 AI에게 시키던 잔소리("두 번 세 번 생각해라", "혼잣말을 길게 적어라")를 최신 똑똑한 AI에게 그대로 시키면, 혼자서 불필요하게 헛생각(CoT)을 하느라 돈만 14.6% 더 들고 일도 서툴러집니다. 쓸데없는 군더더기를 털어내는 것이 진짜 고수의 최적화입니다.
4. **생각의 깊이 조절하기 (Effort Level, 노력 수준)**: 1+1을 푸는 데 우주의 비밀을 깊게 고뇌(Max Effort)하게 만들면 돈 낭비입니다. 어려운 문제는 깊게 생각하고, 쉬운 문제는 가볍게 답하게 만들어야 합니다. 심지어 **"가장 똑똑한 모델을 가볍게 생각하게 만드는 것(High-Tier Low-Effort)"이 "어설픈 모델을 끙끙 앓게 만드는 것"보다 훨씬 싸고 정확합니다.**

## 🔍 2. 기사 전문 맥락 및 핵심 문제의식 전수 분해 (/DEEPDIVE /EXPERT)

### 2.1. 기사 전문의 보도 맥락 및 핵심 취지
AI타임스가 보도한 앤트로픽의 최신 가이드는 생성형 AI 업계가 빠져 있던 '토큰당 단가 착시'를 정면으로 비판합니다.
* **배경**: AI 기업들이 API 가격 경쟁을 벌이면서 입력/출력 100만 토큰당 가격은 계속 떨어졌으나, 정작 기업과 개발자들의 월말 청구 요금은 기하급수적으로 폭증함.
* **원인**: 모델이 복잡해질수록 내부 추론(Thinking / CoT) 토큰이 급증하고, 비효율적인 에이전트 루프로 인해 도구 호출(Tool Call)과 재시도(Retry)가 무한 반복되었기 때문.
* **앤트로픽의 해법**: 단순히 더 저렴한 모델(Haiku, Flash)로 강등하거나 프롬프트를 무작정 줄이는 것이 아니라, **"실제 작업 수행에 필수적인 연산 자원만 정확하게 투입하는 3대 엔지니어링 축"**을 제시함.

### 2.2. 궁극의 평가지표: Cost per Successful Task (CPST)
단순 토큰 단가는 부분 최적화(Local Optimization)의 치명적 함정입니다. 전역 최적화(Global Optimization)의 정량 수식은 다음과 같이 정의됩니다.

$$\text{CPST} = \frac{\sum_{i=1}^{N_{\text{attempts}}} \left( C_{\text{input}}^{(i)} + C_{\text{output}}^{(i)} + C_{\text{thinking}}^{(i)} + C_{\text{tools}}^{(i)} + C_{\text{latency}}^{(i)} \right)}{N_{\text{success}}}$$

* **$C_{\text{input}}$**: KV 캐시 미적중(Cache Miss)으로 발생하는 순수 입력 비용
* **$C_{\text{output}}$**: 최종 에이전트가 출력한 응답 토큰 비용
* **$C_{\text{thinking}}$**: 모델이 내부에서 소모한 추론(Thinking / CoT) 토큰 비용
* **$C_{\text{tools}}$**: 외부 도구 실행 및 라운드트립에 따른 누적 오버헤드
* **$N_{\text{attempts}}$**: Circuit Breaker(3회 실패 제한) 내 총 시도 횟수
* **$N_{\text{success}}$**: 테스트 통과(Exit 0), 린트 통과, 계약 충족을 달성한 유효 성공 ($N_{\text{success}} \in \{0, 1\}$)

### 3.1. 제1기둥: 프롬프트 캐싱 (Prompt Caching) & 접두사 불변성 (Prefix Invariance)
* **메커니즘**: 긴 시스템 프롬프트, 도구 정의, 공통 헌법을 모델 내부의 키-값(KV) 텐서로 변환하여 메모리에 상주시킨 뒤 다음 턴에서 재사용함. 캐시 적중 시 **입력 비용 최대 85~90% 할인 및 응답 지연 시간 80% 단축**.
* **캐시 적중 조건**: 프롬프트의 맨 첫 번째 토큰부터 정확히 일치해야 함.
* **치명적 3대 안티패턴**:
  1. **동적 헤더 주입**: 프롬프트 서두에 `Current Time: 2026-09-12 03:50:00`, `Session-ID: 7f8a-...`를 넣으면 1바이트 차이로 인해 전체 캐시가 무효화됨.
  2. **도구 정의 순서 변경**: 호출 시마다 JSON 도구 명세의 순서가 바뀌면 캐시 미스 발생.
  3. **임계치 미달**: 캐시 최소 임계치(1,024 토큰) 미만의 짧은 프롬프트는 캐싱되지 않음.
* **엔지니어링 수칙**:
  - 시스템 불변 규칙과 정적 도구 정의를 프롬프트 최상단에 1,024 토큰 이상 영구 고정.
  - 가변 메타데이터(타임스탬프, 세션 ID)는 반드시 프롬프트 최하단 사용자 메시지 블록으로 격리.
  - 미사용 도구는 컨텍스트에 상시 올리지 않고 서브에이전트나 지연 로딩(Lazy Loading)으로 분리.

### 3.2. 제2기둥: 지침 부채 (Instruction Debt) 청산 & 6대 안티패턴
과거 LLM(GPT-3.5, Claude 2 시절)의 환각과 오류를 막기 위해 추가했던 방어용 프롬프트들이 최신 프론티어 모델(Claude 3.7 Sonnet, Opus 5, GPT-5/Astra급)에서는 자체 추론 회로와 충돌하여 막대한 비용 낭비를 초래함.

앤트로픽이 실측한 6대 안티패턴과 청산 효과:
* **실측 결과**: 6대 안티패턴 제거(`Prompt Audit`) 시 **비용 14.6% 감소, 정확도 5.3% 향상**.

| 6대 안티패턴 | 과거 구형 모델의 땜질 지침 | 최신 모델에서의 역효과 및 낭비 | 본 프레임워크 청산 기준 |
|:---|:---|:---|:---|
| **① 반복적 중복 검증** | "답변하기 전에 두 번 세 번 다시 확인하라" | 자체 CoT와 충돌하여 무의미한 추론 토큰 과소비 | 텍스트 자가반추 축소, 런타임 코드 검증(Exit 0) 일원화 |
| **② 과도한 장황 서술 요구** | "아주 상세하게 모든 이유와 배경을 서술하라" | 출력 토큰 급증, 핵심 의사결정 은폐, 통신세 폭증 | P1 직설적 능동문 우선, P7 4단 컴팩트 캡슐화 |
| **③ 고정 스크래치패드 강제** | `<thinking>`, `<scratchpad>` 태그 작성 강제 | 모델 네이티브 Thinking 토큰과 이중 중복 계산 | 모델 자체 내장 추론에 위임, 마크다운 태그 강제 폐지 |
| **④ 구형 퓨샷(Few-Shot) 방치** | 2~3년 전 작성된 레거시 예시 10개 나열 | 최신 모델의 내장 지식과 충돌, 컨텍스트 비대화 | 명확한 JSON 스키마 타입 계약 및 최소 단일 대표 예시로 압축 |
| **⑤ 상호 모순 규칙** | "최대한 간결히 답하라" vs "모든 디테일을 기술하라" | 모델의 판단 지연 및 추론 토큰 방황 | P0 권한 우선순위 명문화로 모호성 원천 제거 |
| **⑥ 맹목적 도구 호출 남발** | 사소한 사실 확인에도 불필요한 파일/웹 도구 호출 | 도구 왕복 지연 및 라운드트립 토큰 폭증 | P4 최소 검증 단위 원칙 및 로컬 읽기 우선 |

### 3.3. 제3기둥: 노력 수준 (Effort Level) 조정 및 모델 등급 역전 구조 (Model Inversion)
* **노력 수준의 비선형 비용 곡선**:
  - `Low` ➔ `Max`로 노력 수준을 극대화했을 때:
  - 정답률은 **19.4%p 상승**하는 반면, 작업당 투입 비용은 **3.5배(350%) 폭증**.
  - 단순 질문이나 정형화된 코드 검토에 `Max Effort`를 적용하는 것은 극심한 자원 낭비임.
* **고성능-저추론 역전 구조 (High-Tier Low-Effort Inversion)**:
  - 앤트로픽의 가장 충격적인 실측 데이터:
  - `"하위 모델(Sonnet/Haiku)에게 높은 노력 수준(High Effort)을 주어 끙끙 앓게 만드는 것보다, 최상위 플래그십 모델(Opus)에게 낮은 노력 수준(Low Effort)을 적용하는 것이 비용 대비 성능(CPST)이 훨씬 우수하다."`
  - 최상위 모델의 강력한 기본 지능을 바탕으로 군더더기 추론 없이 핵심만 즉각 도출하는 것이 속도, 비용, 정확도 전 영역에서 파레토 최적(Pareto Optimal)을 달성함.
* **CLI 지원 도구**:
  - `/claude-api hillclimb`: 최적의 (모델 계층, 노력 수준) 조합을 탐색하는 자동화 명령.
  - `/claude-api cost-optimize`: 캐싱, 출력 제한, 배치 처리 종합 분석.
  - `/claude-api prompt-audit`: 프롬프트 내 6대 지침 부채를 자동 탐지하여 제거.

### 4.1. OpenAI Codex (대뇌 피질 / 최고 사령관)
* **위치**: 상위 추론 및 P2 거버넌스 총괄.
* **보편 적용**:

  2. **접두사 불변성 85% 할인**: 시스템 프롬프트 첫 1,024 토큰에 사령관 헌법 및 JSON-RPC 스키마를 고정하여 매 턴 85% 캐시 할인 달성.
  3. **지침 부채 청산 (Zero Code Pollution)**: 소스코드를 통째로 넘기는 낡은 방식을 철폐하고, Ollama가 추출한 AST 스켈레톤(300 토큰)만 주입.

### 4.2. Claude Code (면역계 / 전문 실행기)
* **위치**: 소스코드 작성, 파일 수정, 로컬 컴파일/테스트.
* **보편 적용**:
  1. **High-Tier Low-Effort 적용**: Pro 요금제 최상위 모델(Opus 5급)을 기반으로 하되 불필요한 깊은 추론을 절제하고, 5시간 윈도우 한계에 대비해 3단계 생명유지 프로토콜(Opus ➔ Sonnet ➔ Ollama) 가동.
  2. **프롬프트 캐싱 극대화**: `~/.claude/CLAUDE.md` 및 프로젝트 규칙을 불변 접두사로 유지하여 90% 캐시 적중 확보.
  3. **지침 부채 청산**: 과거 지침들을 `/claude-api prompt-audit` 수준으로 정제하여 이중 자기검증 루프를 차단하고 즉각적인 셸 컴파일 검증(Exit 0)으로 대체.

### 4.3. Antigravity (감각기 / 실시간 오케스트레이터)
* **위치**: 환경 센싱, 로그 수집, 파일 변경 감지, 대화 조율.
* **보편 적용**:
  1. **지침 부채 청산의 선구자**: 매 턴 강제되던 장황한 일일 업무 보고 상용구를 영구 삭제하고, 오직 상태 변이 발생 시에만 4단 컴팩트 결과 캡슐(Outcome, Verification, Risks, Next) 출력.
  2. **11,800자 엄격 상한 준수**: 시스템 규칙을 11,534자로 압축하여 버퍼 266자를 확보함으로써 프롬프트 캐시 로딩 무결성 수호.
  3. **도구 지연 로딩 (Lazy Tooling)**: 빈도가 낮은 무거운 MCP 도구는 상시 로드하지 않고 필요 시 서브에이전트로 분리 위임.
